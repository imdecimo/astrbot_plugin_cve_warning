# astrbot_plugin_cve_warning

基于 **CISA KEV**（Known Exploited Vulnerabilities，已在野被利用漏洞目录）的**增量**漏洞预警插件：
只在 KEV 目录真正新增条目时推送，一轮新增合并成一条消息，可选中文摘要，按会话补发。

- 数据源：CISA KEV JSON Feed（catalogVersion 判定新增）
- 补充数据：NVD（仅用于取 CVSS 分数，带本地缓存）
- 中文摘要：使用 AstrBot 已配置的聊天模型，失败自动降级为英文原文
- 推送目标：在配置里指定会话，支持多会话、支持按会话补发

## 行为说明

这一节是 v2 与 v1、以及与其他"漏洞订阅"插件最容易混淆的地方，请先读完。

1. **首次启动只建立基线，不推送任何历史漏洞。**
   第一次运行时插件会把当前 KEV 目录里的全部条目记为基线，日志出现
   `已建立基线，共 N 条，本轮不推送`。此后每轮只推送**真正新加入 KEV** 的条目，
   不会把历史漏洞当新漏洞刷一遍。

2. **目录版本未变时不做任何解析，也不查 NVD。**
   插件用 KEV 的 `catalogVersion` 与 ETag 判定目录是否变化。没变化时这一轮几乎零开销，
   所以 `push_interval_hours` 可以放心调小。

3. **一轮新增合并成一条消息。**
   同一轮里发现的多条新增会合并进一条摘要消息，不是一个 CVE 一条消息。
   只有当条目数超过 `max_items_per_message` 时才分屏发送，标题会标注 `（1/3）` 这类分页号。

4. **全部推送，不按严重度过滤。**
   KEV 里的条目都是"已确认在野被利用"，所以不做 Critical/High 过滤。
   消息内按 CVSS 分数降序排列；查不到 CVSS 的条目排在后面，按加入日期降序。

## 中文摘要

中文摘要依赖 **AstrBot 已配置的聊天模型**（`enable_ai_summary`，默认开启）：

- 模型不可用、调用超时（`summary_timeout_seconds`）或调用失败时，**自动降级为 KEV 英文原文**
  （截断到 120 字），推送照常进行，不会因此漏推。
- 摘要只影响描述文字，不影响条目是否推送。
- 想关掉摘要（例如没有可用的聊天模型）：把 `enable_ai_summary` 设为 `false`。

## 配置说明

插件的配置项定义在 `_conf_schema.json`，在 AstrBot WebUI 的插件配置里修改。

| 配置项 | 类型 | 默认值 | 说明 |
|---|---|---|---|
| `enabled` | bool | `true` | 是否启用插件。关闭后不会启动定时任务。 |
| `admin_users` | list | 空 | 插件管理员列表（QQ 号等），可执行状态查询与手动刷新。 |
| `target_sessions` | list | 空 | 推送目标会话，格式见下。留空则只更新基线、不推送。 |
| `kev_feed_url` | string | cisa.gov 官方地址 | CISA KEV JSON 数据源，除非自建镜像否则不建议改。 |
| `http_proxy` | string | 空 | KEV/NVD 请求使用的代理，例如 `http://127.0.0.1:7890`；留空直连。 |
| `push_interval_hours` | int | `6` | 拉取间隔（小时），范围 1–48。目录未变时几乎零开销。 |
| `max_items_per_message` | int | `15` | 单条消息最多包含几条 CVE，超出分屏。 |
| `failure_notify_sessions` | list | 空 | 刷新/拉取抛异常或 KEV 目录解析异常时通知的会话；留空只写日志。 |
| `nvd_api_key` | string | 空 | NVD API Key（可选）。配置后限流更宽松；留空也能查，但更容易失败。 |
| `cvss_cache_ttl_days` | int | `30` | CVSS 缓存过期天数，过期后重新查 NVD。 |
| `enable_ai_summary` | bool | `true` | 是否用已配置的聊天模型生成中文摘要。 |
| `summary_timeout_seconds` | int | `60` | AI 摘要超时（秒），超时即降级为英文原文。 |

### target_sessions 怎么填

格式：**`平台:消息类型:会话ID`**

```text
aiocqhttp:GroupMessage:123456789
```

在**目标群/会话里发送 `/sid`** 指令即可拿到本会话的这段标识，直接复制过来即可。
可填多个，一行一个（WebUI 列表里逐条添加）。

> 注意：`failure_notify_sessions` 只在"拉取/刷新抛异常"或"KEV 目录解析异常"时通知，
> 发送报错不会触发它。它和 `target_sessions` 一样使用 `平台:消息类型:会话ID` 格式。

## 命令

| 命令 | 权限 | 说明 |
|---|---|---|
| `/CVE漏洞推送` | 所有人 | 显示帮助。 |
| `/CVE漏洞推送状态` | 管理员 | 查看运行状态：是否运行、状态是否落盘、目录版本、基线条数、上次拉取/推送时间、下次运行时间、待补发会话与尝试次数、上轮适配器报错会话数、累计放弃补发次数、AI 摘要状态。 |
| `/CVE漏洞推送手动刷新` | 管理员 | 立即拉取一次并按需推送。 |

管理员判定：AstrBot 平台自身的 `is_admin()` 为真，**或**发送者 ID 在 `admin_users` 列表中。

`/CVE漏洞推送状态` 里的两个措辞要特别说明：

- **上轮适配器报错会话数**：上一轮"发送适配器报错"的会话**个数**（不是条数）。
- **累计放弃补发次数（按会话×轮次计）**：同一个会话在一轮里被放弃，记 1 次；
  统计单位是"会话×轮次"，不是 CVE 条数。

`/CVE漏洞推送手动刷新` 的几种结果：

- `已推送新增 N 条`：本轮有新增并已发出。
- `本轮无新增，只补发了此前未送达的内容`：目录没新增，但某些会话还有待补发内容，本轮补发完了。
- `KEV 目录解析异常：本轮未推送，下一轮会重试`：拉到的目录内容与自称的条数明显不符
  （例如解析出 0 条），插件宁可不动基线也不推送脏数据。该轮会通过 `failure_notify_sessions` 报警，
  目录版本与基线**都不会推进**，下一轮自动重试。
- `目录版本未变，无新增` / `已建立基线，本轮不推送` / `未配置推送会话，仅更新基线`：见字面意思。

## 发送失败的处理

**判定口径：适配器是否报错。不是"用户是否看到"。**

- 插件调用 AstrBot 的发送接口时，如果**抛异常**（例如 `ActionFailed`、找不到平台实例），
  就判定这个会话本轮没有送达：
  - 该会话本轮的内容（新增 + 之前积压的补发内容）进入**这个会话自己的待补发队列**；
  - **下一轮**（哪怕 KEV 目录完全没变）会继续尝试发送，新数据到来时与补发队列按 CVE 编号去重合并重发；
  - 同一个会话**连续 3 次**适配器报错后放弃补发、清空该会话队列（这一轮积压的内容不再重试），
    并记一条 error 日志；该会话后续轮次的新内容仍会照常尝试发送。
- 待补发队列按会话隔离：一个群发不出去，不影响其他群。
- 某个会话被从 `target_sessions` 里移除后，它的待补发队列会被丢弃，避免很久以后被加回来时整批旧内容突然涌出。

**能力边界（重要）：** 如果协议端返回成功、但消息实际被平台拦截、风控或静默丢弃，
插件**无法检测**，也**不会补发**。也就是说"适配器报错"能被发现并补发，
"用户没看到"发现不了。请不要把本插件当成送达保证。

## 数据存储

状态文件固定在 AstrBot 的插件数据目录下：

```text
data/plugin_data/astrbot_plugin_cve_warning/state.json
```

里面保存三部分内容：

- **基线**：KEV 目录版本、ETag、全部见过的 CVE 编号及其 `dateAdded`（判定"新增"的依据）；
- **CVSS 缓存**：从 NVD 查到的分数/等级及其写入时间（按 `cvss_cache_ttl_days` 过期，上限 5000 条）；
- **按会话的待补发队列**：每个会话未送达的内容块与已尝试次数（每会话上限 50 条）。

写入采用"临时文件 + 原子替换"，不会出现半截 JSON。

**状态目录不可写时，插件降级为纯内存态，不会写到任何其他位置。**
此时基线与补发队列只存在于本次运行内存里：`/CVE漏洞推送状态` 会显示
`状态落盘: 否（状态目录不可写，本次运行仅内存态）`，重启后基线丢失，
下一轮会被当成首次启动重新建立基线（也就是那一次不会推送）。

### 从 v1 升级

v2 首次启动读到 v1 的状态文件时会自动迁移（把 v1 的已推送/已见/已压制三本账取并集作为基线，
清理无效的 CVSS 缓存），并在同目录留下备份：

```text
data/plugin_data/astrbot_plugin_cve_warning/state.v1.json.bak
```

迁移后 `schema_version` 为 `2`。因为基线取的是并集，升级后**不会**把 v1 里被严重度过滤挡下的历史 CVE
当成新增刷一遍。

## 安装

1. 把插件目录放到 AstrBot 的插件目录（或通过 AstrBot 插件管理安装）；
2. 按需在 WebUI 填 `target_sessions`（在目标群发 `/sid` 获取）；
3. 重启/重载 AstrBot，确认日志出现 `已建立基线，共 N 条，本轮不推送`
   （首次运行这是正常现象，不是故障）。
